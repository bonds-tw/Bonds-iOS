# MyData 驗證與返回流程：相容性修正

## 決策

從回退後的 `37f35df` 主線出發，選擇性沿用 kidney 的 PR #65 原始提交
`767a388`。MyData 的身分驗證由官方頁面決定；有備而來負責保留網頁、
處理行動自然人憑證的 App 切換，以及沿用既有下載、匯入和簽章流程。

官方登入頁提供多種身分驗證方式，但個別資料、裝置及申辦條件可能不同。
App 不把任何一種方式宣稱為所有文件皆可用，也不以本機是否安裝
MobileMoica 決定能否進入 MyData。

- 官方頁面：https://mydata.nat.gov.tw/signin
- 原始貢獻：https://github.com/bonds-tw/Bonds-iOS/pull/65

## 沿用與調整

| 原始 PR 項目 | 本次處理 |
| --- | --- |

## 維持原樣的流程

- 使用相同的 WKWebView 與網站資料儲存區；從憑證 App 回來不重新載入頁面。
- 只攔截 `mobilemoica:`，其他登入網頁、JavaScript 對話框及下載政策照舊。
- Keychain 自動填寫仍限官方 MyData 頁面；原檔儲存、ZIP/PDF 處理、
  個人文件的連續匯入及延後下載狀態不變。
- 完成畫面改依目前 snapshot 辨識分區，修正移除引導區後地址列被歸錯區的既有問題。
- `CredentialIssuance`、TW FidO 用戶端、broker、公文簽章與 ZK 簽章程式碼不變。
  卡片仍需原本的行動自然人憑證簽章；以其他方式登入 MyData 不會略過這一步。
- 回到 App 僅更新「返回」引導，不當作驗證完成或領卡成功。

## 驗證範圍

自動測試涵蓋無本機憑證 App 的入口、一般網址不被攔截、大小寫 scheme、
開啟失敗與重試、重複導航、返回後不觸發匯入完成、解鎖前後同一彈窗及
輸入保留、報告過濾、原有錯誤指引、大字體捲動，以及既有單元測試。

模擬器 UI 測試檢查 MyData 入口與背景返回、錯誤報告的大字體操作。
Release 的既有簽章檢查繼續由 CI 執行。

上述測試不等於真人完成 MyData 驗證。真機仍需分別確認：

1. 選行動自然人憑證，確認後回到同一 MyData 頁並完成下載。
2. 選官方頁面當次提供的其他方式，完成驗證與下載。
3. 個人文件連續匯入，以及延後完成文件的續辦。
4. 國民身分證資料下載後，接續既有簽章並看到實際儲存的卡片。
